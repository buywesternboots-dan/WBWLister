# BootLister — seller interface for westernbootworld.com (WBW)

## Working rules
- Minimize lines of code; simple, clean, accurate, fully functional.
- Don't report changes — only problems or questions.
- Outline before building when asked; don't build until told.
- Fix problems and make judgment calls without asking; ask only when truly necessary.
- Tell me when a session is getting too long and give a copy-ready summary.

## Context
- This repo is an MVP for testing; production will run on another machine, GitHub and Vercel (not the user's). Keep it portable: config via env vars, nothing tied to these accounts.
- WBW: custom marketplace for cowboy/western boots, built by another developer. I have full backend access, but we're building against a mock WBW for now.
- Stack: Next.js on Vercel. No marketplace APIs; data comes from customer-facing pages.
- Goal: sellers import listings (Facebook Marketplace first; eBay, Poshmark, Depop later), review, edit, manage inventory, publish on WBW.
- Facebook blocks server access, so collection runs in my browser via a Chrome extension. I import sellers' Marketplace profiles while logged into my own FB (with seller permission). FB photo links expire, so photos are copied at import. Bulk import is human-paced (3–6 s per listing).

## Folders
- Repo root: Next.js app (no web/ subfolder).
  - lib/wbw.js: mock WBW layer (Neon Postgres + Vercel Blob). Replace only this file to connect to real WBW. Table auto-creates.
  - app/api/items/route.js: GET list by status, POST create, PATCH bulk actions. An admin picks a seller with Authorization: Bearer (required; no demo default). A seller session ignores Bearer and is locked to that seller. Logins (proxy.js + lib/session.js + lib/gate.js + lib/auth.js): WBW staff sign in with the username admin and ADMIN_PASSWORD (if ADMIN_PASSWORD is unset, APP_PASSWORD is the staff password). That password is an env var, compared in constant time, and is not stored. APP_PASSWORD signs the session cookie; if it is unset, ADMIN_PASSWORD signs it. Changing the signing secret signs everyone out. TEAM_EMAIL and TEAM_PIN are no longer used. Sellers register themselves (POST /api/register) with a shop name plus an email or a phone number (or both) and a password of at least 8 characters. The password is scrypt (sellers.login_salt + sellers.login_hash prefixed scrypt$) and is never the cookie. An old SHA-256 PIN does not count as a password; registering with that email or phone claims the existing seller row. Same sign-in form, then two screens (lib/home.js): an admin goes to / with every tool; a seller goes to /seller with only their own items (import, review, export, sync — no seller admin, move, or delete). proxy.js sends a session that opens the other screen back to its own. Every /api route resolves the signed session itself (lib/access.js); a seller cannot read or change another seller's rows. Deployed with no admin password (NODE_ENV=production, or VERCEL_ENV production or preview) the site returns 503. Local dev with neither secret stays open. A seller reviews their own listings (yellow guessed values included) and approves each one; items.approved_by stores their email or phone and items.approved_at the time. Approving a listing publishes it immediately (status published). There is no second click and no admin step. lib/publish.js pushStub is the export and sync stand-in; the item is marked exported here and nothing is sent to WBW. The admin still sees and edits every listing. A seller edit of a live item clears the approval and returns it to Newly imported. Admin-only API actions (delete, move, seller settings, id check, photo backfill) are rejected for a seller session. The extension POSTs /api/login and sends that session token as x-auth. GET /api/me says which (admin or seller). Sellers: sellers table via app/api/sellers — "+ Add seller" / Seller settings form: details, import & sync (website, FB profile, sync preference — auto-sync not built yet), listing style (notes; terms "shorthand = meaning" used only to read listings; defaults "field = value" when listing is silent) — applied by enrichFor(); setup required before Import/Sync; page header dropdown, one seller at a time. The form does not set a password.
  - lib/wbw.js FIELDS = WBW listing fields (the Sell a pair form: title, asking price, brand, sized for, size, size estimated, condition, width, material type, hide, cut, where made, color, keywords, sole length/width, heel height, shaft circumference/height, sole, heel, toe, description); enrich() fills them from listing text; values inferred from free text are listed in items.guessed and shown yellow until the seller saves (= verified). CSV columns in app/screen.js CSV (WBW Seller Name, then Photos, then those fields).
  - app/page.js: inventory page (tabs Newly imported / Exported / Pending sold / Sold / Removed / Archived — Sync: listings gone from the source → Pending sold (seller "Mark sold"/"Still for sale"; auto Sold after 30 days); source-changed listings → back to Newly imported with "Changed at source" (items.changed_at, cleared on save); Removed → Archived after 30 days; groups Boots / Belts / Not sure / Other (items.boot + items.boot_score from classify() in lib/wbw.js; Boots/Belts only when ≥97% sure); group header quick filters Ready / To verify / Missing <field>; search with brand-family & material synonyms; sort most-likely-boot or newest; bulk lower price, Export CSV for WBW import (columns in CSV const; production will connect directly to WBW instead), remove, restore, Move to seller, Delete (permanent, incl. Blob photos); tap to edit). Each item keeps source_url (seller-website product page → 'Seller Website Link' for WBW to link back; FB listing link for reference).
  - Env: DATABASE_URL, BLOB_READ_WRITE_TOKEN, ADMIN_PASSWORD (staff password typed at sign-in; username admin; not stored), APP_PASSWORD (session signing secret; also the staff password when ADMIN_PASSWORD is unset; also the signing secret when it is the only one set). Neither set: production and Vercel preview return 503; local dev stays open. TEAM_EMAIL and TEAM_PIN are retired. EBAY_CLIENT_ID, EBAY_CLIENT_SECRET.
- lib/vocab.js: shared brands (with families, e.g. Rios), materials (aliases, longest wins: HBL = Caiman Lizard), edit-form suggestions (CHOICES; free text always allowed), search.
- Import rules: each failed item is retried twice before counting as failed; every photo must import (max 30) or it fails; gender defaults Men; width not required and never defaulted: blank when not in the listing, shown red as a heads-up (ALERT in app/screen.js); condition New only if explicit, Custom Made when the listing says custom made or made to order, else Broken In.
- lib/ebay.js: eBay via the official Browse API (client-credentials token; seller search in category 11450, details 20 at a time; item specifics → fields). Seller link must be the username (ebay.com/usr/<name>). Untested until API keys are added.
- lib/sites.js + app/api/import: Poshmark closets (server-side; the closet feed carries full listing details, 48 per request, so a closet is a handful of requests — keep it that way for daily syncs; link poshmark.com/closet/<user> goes in the seller's Website field) and website stores (Wix/Shopify…) imported server-side from sitemap + schema.org Product data; "Import from website" box on the inventory page (uses the selected seller's website; Shopify collection links import just that collection). Import = new only; Sync = re-read all, refresh source-changed items (items.src_hash fingerprint of source data, so seller edits are not seen as changes), gone/sold → Pending sold.
- Depop (Cloudflare blocks servers): extension opens the shop once and reads Depop's own listing feed (webapi.depop.com shops/{id}/products, page context) — readDepopShop()/importDepop() in extension/background.js; photos linked (permanent). Seller's Depop link goes in the fb_profile field.
- Inventory page Import/Sync works for every seller: website links run server-side; Facebook/Depop links are handed to the extension via extension/bridge.js (content script on the app's pages; progress posted back to the page).
- lib/http.js: shared route helpers (handle, guardAction). lib/access.js: actorFrom / sellerFor on every /api route.
- Extension download: scripts/zip-extension.mjs packs extension/ into public/bootlister.zip at build; "Chrome extension" link in the page header (with install steps when needed). bridge.js sets the popup's server address on first visit.
- extension/: Chrome extension (MV3). background.js: page readers (readListing, collectIds, readDepopShop) + one shared importAll loop; one import at a time; messages { type: 'link', link, sync } or { type: 'listing', tabId }. Popup (server URL, email or phone or admin, password, seller dropdown [fills their saved FB/Depop link], profile link, "Import all from this profile", "Sync with this profile" [re-reads all; source-changed items refreshed; unlisted → Removed], "Add this listing"), right-click "Add to BootLister". Sign in once with the email, phone, or admin username and the password. FB reader uses og meta tags + text labels; untested against real pages.
